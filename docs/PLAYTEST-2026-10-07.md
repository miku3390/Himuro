## 问题一：角色完全不符合设定，回复千篇一律

### 现象

每局对话回复很快，但质量都不高，回复结尾永远是同一句「所以——接下来你想做什么？」，忍野扇的谜语少女人设完全没有体现。

### 根因 A（主因，已查实）：Base URL 停留在 mock，根本没走真模型

- 设置页里轻量/高质量档的**模型名已填**（「私人用ds」——显然是打算接私有 DeepSeek 端点），但 **Base URL 仍是 `mock`**；
- `mock` 是内置演示模型（`lib/llm.ts`），回复是写死的模板，`llm.ts:54` 的模板结尾正是「所以——接下来你想做什么？」——与用户看到的完全吻合；
- 也就是说：**角色卡、世界书、记忆层全都没参与生成**，当前所有对话都是本地模板在演。

**两分钟自救**（不用等任何开发）：设置页 → 轻量档 Base URL 填私有端点（形如 `http://<内网地址>/v1`）→ 填 API Key → 点「测试连接」看到「连接正常」→ 保存。高质量档同理。

### 根因 B（接真模型后仍会影响质量的三处弱点，`lib/prompt.ts`）

1. **示例对话只是 system 文本**：目前以「# 对话示例（学习语气与节奏…）」拼在系统提示里。对角色扮演而言，把示例改成 **few-shot 消息（user/assistant 交替进 messages 数组）** 是公认更大的杠杆；
2. **无采样参数控制**：temperature / top_p / max_tokens 全部走默认值，路线图本就列了「更多采样参数」待做——扮演类任务对 temperature 敏感；
3. **无反重复指令**：真模型也可能养成固定收尾（如每次都以提问结尾），prompt 里没有针对性约束。

### 方案

| # | 方案 | 改动范围 | 工作量 | 预期效果 | 风险 |
|---|---|---|---|---|---|
| 1-1 | **mock 检测提示条**：聊天页检测到当前档位 `baseUrl === "mock"` 时，顶部显示「正在使用演示模型，回复为内置模板 → 去设置页接入」一键跳转 | `ChatRoom.tsx` 顶栏 | S | 根因 A 不再被无声踩坑；新用户开箱即懂 | 无 |
| 1-2 | **示例对话 few-shot 化**：`generateOneReply` 把 `character.examples` 拼成 user/assistant 交替消息插在 system 之后、最近消息之前（mock 模式不受影响） | `lib/chatEngine.ts`、`lib/prompt.ts` | M | 角色语气遵从度显著提升（few-shot > system 描述） | 上下文变长，注意与 VERBATIM_WINDOW 的总预算 |
| 1-3 | **采样参数进设置页**：temperature / top_p 每档位可调，存 settings 表；llm.ts 透传 | schema+迁移、`SettingsForm`、`lib/llm.ts` | M | 扮演类任务可调高 temperature 求活；顺手完成路线图「更多采样参数」 | 需要一次迁移 |
| 1-4 | **反重复收尾指令**：系统提示追加「不要每轮以相同句式收尾，禁止模板化提问」之类硬指令 | `lib/prompt.ts` | S | 缓解模板腔 | 指令类手段效果因模型而异 |

**推荐组合**：1-1 立刻做（S）；接通真模型后观察，仍不满意再上 1-2 → 1-4 → 1-3。

## 问题二：语音播放流程太繁琐（点试听 → 再点下拉菜单里的播放）

### 现象

GPT-SoVITS 供应商下，长回复点「▶ 试听」不直接出声，而是先展开逐段面板，还要再点一次「▶ 全部播放」。

### 根因

v1.6 的交互决策：长文本（>2 段）默认展开分段面板，本意是给「逐段下载」一个入口，但把「我就想听一下」的高频路径变成了两步。

### 方案

| # | 方案 | 改动范围 | 工作量 | 预期效果 | 风险 |
|---|---|---|---|---|---|
| 2-1 | **试听默认直接播**：点「▶ 试听」= 立即逐句顺序播放（按钮上显示「▶ 2/5 段」进度，再点变「⏹ 停止」）；分段面板拆成独立小按钮「⤓ 分段」，只在要逐段下载时展开 | `ChatRoom.tsx`、`lib/tts.ts` | S | 高频路径一步到位；缓存已在（重听同一句不重新合成） | 面板仍保留，功能无损失 |
| 2-2 | **边合成边播 + 预取**：第一段合成完立刻播，后台预取后续段落，消除段间等待 | `lib/tts.ts` | M | 长回复的体感等待接近单段 | 并发 2 路 GPT-SoVITS 请求，单卡显存需实测 |
| 2-3 | **「继续朗读下一条」**：一条播完自动接星标/下一条，听书模式 | `ChatRoom.tsx` | S | 连听场景 | 与「导出配音」功能重叠度高，优先级低 |

**推荐**：2-1 必做；2-2 视单卡压力实测后决定。
